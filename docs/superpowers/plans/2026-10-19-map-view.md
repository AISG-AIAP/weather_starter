# Map View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make an interactive Leaflet map of Singapore the default view of the app's Hero panel, showing every saved location as a pin with a lightweight weather popup on click, alongside a persistent toggle back to the existing detail view.

**Architecture:** A new `MapView` component (react-leaflet `MapContainer` + `TileLayer` + one `Marker` per location, each carrying a `Popup`) replaces the Hero's content when a new local `view` toggle is set to `'map'` (the default); the existing detail-cards JSX is otherwise untouched and shown when `view === 'details'`. Marker icons are driven by a condition string already present on every location (zero extra requests); the popup's exact temperature is fetched lazily per-pin on click, reusing the `getEnrichedWeather` cache already built in a prior session. A small pure classifier function (`classifyCondition`) is extracted from two existing components to remove duplicated keyword-matching and to drive the new marker/popup icons too.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS, `leaflet` + `react-leaflet` (already installed, unused), `vitest` (backend-only today; extended to cover one new frontend unit).

**Spec:** [docs/superpowers/specs/2026-10-19-map-view-design.md](../specs/2026-10-19-map-view-design.md)

## Global Constraints

- Backend: no changes. Use only the existing `GET /api/locations` and `GET /api/locations/:id/weather-rich` endpoints.
- Never fetch enriched weather (`getEnrichedWeather`) for more than one location at a time automatically — only in response to a user clicking that location's pin. Marker icons must use only `location.weather.condition`, already present on every location from the cheap list endpoint.
- The existing "Details" view (current `Hero.tsx` JSX when a location is selected, and its "Select a location" empty state) must render pixel-identical to today — this work is additive only.
- Map re-fits bounds only when the set of location IDs changes (add/remove), never on a same-ID weather refresh.
- Selecting a location via the Sidebar has no effect on the map (no pan/zoom/highlight); only marker-click → `select(id)` flows, never the reverse.
- No marker clustering, dragging, map-click-to-add, or full-screen/modal expansion.
- No React/DOM component-testing library is set up in this project (only backend `vitest` tests exist). Follow the existing frontend convention: components are verified manually in the browser, not with automated render tests. The one exception is the new `classifyCondition` function (pure logic, no DOM) — it gets a real `vitest` unit test, which requires widening `vitest.config.ts`'s `include` glob to also cover `frontend/src`.
- Project convention (`.claude/CLAUDE.md`): TS/TSX files should stay under ~300 lines; a components folder should stay under ~8 files before splitting into subfolders. `frontend/src/components/` is already at 17 files (pre-existing debt, not introduced by this plan) — to avoid making that worse, the two map-specific files go in a new `frontend/src/components/map/` subfolder; `classifyCondition` stays at the top level next to `format.ts`/`icons.tsx` since it's shared by non-map components too.

## Review Focus

- Zero saved locations: the map must render (centered on Singapore, no markers), not crash or show a blank screen.
- A location whose `weather.condition` is `null`/empty (never refreshed, or last refresh failed): marker icon must fall back to a sensible default category, not throw.
- The popup's enriched-weather fetch fails (e.g. the backend returns 502 because the upstream API is rate-limited): the popup must show a clear "unavailable" state, never hang in a permanent loading spinner.
- Clicking a second pin while the first pin's popup fetch is still in flight: each popup's loading/result state must stay independent — no cross-pin flicker or stale overwrite.
- After selecting a location by clicking its pin, switching to "Details" via the toggle must show that same location's detail panel (the one specified cross-component wire this feature adds).

### Task 2: MapView — map, tiles, markers, fit-bounds

- [ ] **Step 1: Add Leaflet popup/container theme overrides to `frontend/src/index.css`**

  Append rules overriding `.leaflet-popup-content-wrapper` and `.leaflet-popup-tip` to a dark background (`#1b2430` or equivalent to the app's existing glass-card tone) with light text, and set `.leaflet-container` to inherit the app's font. - [ ] **Step 2: Implement `conditionIcon` in `frontend/src/components/map/conditionMarkerIcon.tsx`**

  `export function conditionIcon(category: ConditionCategory, className: string): ReactElement`, a `switch (category)` returning, per this exact mapping, `<Icon className={`${className} text-COLOR`} />`: `thunderstorm` → `CloudLightningIcon` text-yellow-300; `rain` → `CloudRainCheckIcon` text-blue-300; `snow` → `CloudSnowIcon` text-cyan-200; `clear` → `CloudCheckIcon` text-yellow-400; `cloudy` (default) → `CloudIcon` text-white/80. - [ ] **Step 3: Implement `MapView` in `frontend/src/components/map/MapView.tsx`**

  - Import `'leaflet/dist/leaflet.css'` at the top of this file.
  - `const SINGAPORE_CENTER: [number, number] = [1.3521, 103.8198];` `const DEFAULT_ZOOM = 11;`
  - Render `<MapContainer center={SINGAPORE_CENTER} zoom={DEFAULT_ZOOM} className="h-full w-full rounded-2xl">` with a `<TileLayer url="https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png" attribution="&copy; OpenStreetMap contributors" />`.
  - Inside `MapContainer`, render one `<Marker>` per location, `position={[location.latitude, location.longitude]}`, `icon={buildMarkerIcon(classifyCondition(location.weather.condition))}`, with an `eventHandlers={{ click: () => onSelect(location.id) }}`.
  - `buildMarkerIcon(category: ConditionCategory): L.DivIcon` — use `renderToStaticMarkup` (from `react-dom/server`) to render a small wrapper (`<div className="flex h-9 w-9 items-center justify-center rounded-full border border-white/25 bg-slate-900/90 shadow-lg shadow-black/40">`) containing `conditionIcon(category, 'h-5 w-5')` from Step 2. Set `className: 'weather-marker'` (not empty) specifically to suppress Leaflet's default white-square `div-icon` background class — add a one-line `.weather-marker { background: none; border: none; }` rule alongside Step 1's CSS.
  - Also render a `FitBoundsToLocations` child component (defined in this same file, not exported) inside `MapContainer`: `const map = useMap();` then a `useEffect` keyed on a string built by sorting `locations.map(l => l.id)` and joining with `,` — if `locations.length === 0`, call `map.setView(SINGAPORE_CENTER, DEFAULT_ZOOM)`; otherwise build `L.latLngBounds(locations.map(l => [l.latitude, l.longitude]))` and call `map.fitBounds(bounds, { padding: [40, 40], maxZoom: 15 })`.

### Task 3: MapPinPopup — lazy enriched-weather popup

**Files:**
- Create: `frontend/src/components/map/MapPinPopup.tsx`
- Modify: `frontend/src/components/map/MapView.tsx`

**Interfaces:**
- Consumes: `getEnrichedWeather(id: number): Promise<WeatherSnapshot>` from `frontend/src/api.ts` (already exists). `classifyCondition` from Task 1 (`../conditionCategory`). `conditionIcon(category: ConditionCategory, className: string): ReactElement` from Task 2 (`./conditionMarkerIcon` — **not** from `MapView.tsx`; importing from `MapView.tsx` here would be circular, since `MapView.tsx` imports `MapPinPopup`). `formatTemperature` from `frontend/src/components/format.ts` (already exists).
- Produces: `export interface MapPinPopupProps { location: Location }` and `export function MapPinPopup({ location }: MapPinPopupProps)`.

- [ ] **Step 1: Implement `MapPinPopup` in `frontend/src/components/map/MapPinPopup.tsx`**

  - Local state: `status: 'loading' | 'ready' | 'error'` (initial `'loading'`), `enriched: WeatherSnapshot | null` (initial `null`).
  - `useEffect` keyed on `location.id`: set `status` to `'loading'`, call `getEnrichedWeather(location.id)`, on success set `enriched` and `status: 'ready'`, on failure set `status: 'error'`. Guard with a `cancelled` flag set in the cleanup function so a fetch that resolves after the popup for a *different* location has mounted in its place never writes to this instance's state.
  - Name shown: `location.weather.area || `${location.latitude.toFixed(3)}, ${location.longitude.toFixed(3)}`` (same fallback pattern `Hero.tsx` already uses).
  - Condition for the icon: `const condition = enriched?.condition ?? location.weather.condition;` (use the richer value once available, the cheap one while loading) then `conditionIcon(classifyCondition(condition), 'h-6 w-6')` to render it — same mapping the marker itself uses, at popup scale.
  - Temperature: `status === 'ready' ? enriched?.temperature_c ?? null : null`, rendered through `formatTemperature` — while `status === 'loading'`, show `'…'` instead of calling `formatTemperature` (so the user can tell loading apart from a confirmed-unavailable `'--'`).
  - On `status === 'error'`, show a small `"Weather unavailable"` line under the name/icon instead of a temperature.
  - Layout: a small centered block (`min-w-[10rem] text-center`) — name on top, condition icon + temperature/status below, matching the glass-popup theme from Task 2 Step 1.

- [ ] **Step 2: Wire `MapPinPopup` into `MapView`'s markers**

  In `MapView.tsx`, add `<Popup><MapPinPopup location={location} /></Popup>` as a child of each `<Marker>`.
